# WEBSOCKET_SPEC.md — Signal Clone

## Connection

```
ws://localhost:8000/ws
wss://<backend-domain>/ws
```

### Authentication
- Authentication is strictly performed using the existing HTTP-only `session_token` cookie during the WebSocket upgrade handshake.
- Raw session tokens are NEVER passed in query parameters or exposed to client JavaScript.
- Server validates cookie against `sessions` table (SHA-256 hash lookup).
- If cookie is missing, invalid, or expired: server closes connection immediately with code `4001` ("Authentication failed").
- If valid: server registers connection and sends `connection.ready` event.

### Connection Lifecycle

```
Client                              Server
  │                                    │
  ├── WS Handshake (Cookie) ──────────►│
  │                                    ├── Validate session_token cookie
  │                                    ├── Register connection
  │◄── connection.ready ──────────────┤
  │                                    │
  │    ... bidirectional events ...     │
  │                                    │
  ├── WS Close ───────────────────────►│
  │                                    ├── Unregister connection
  │                                    │
```

### Multiple Connections
- A user may have multiple simultaneous WebSocket connections (e.g., multiple browser tabs)
- All connections for a user receive all events for that user
- Connection Manager maintains: `Map<user_id, Set<WebSocket>>`

### Reconnection & Offline Delivery
- Client implements automatic reconnection with exponential backoff.
- On reconnect: client re-fetches server state via REST API (`GET /conversations/{id}/messages`).
- Server does NOT queue events for offline users — durability is guaranteed via SQLite persistence before broadcast.
- Recommended backoff: 1s, 2s, 4s, 8s, 16s, 30s (cap)

## Event Envelope

All WebSocket messages use a consistent JSON envelope:

```json
{
  "type": "event.name",
  "event_id": "uuid",
  "timestamp": "2024-01-15T10:30:00Z",
  "payload": { ... }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `type` | string | Event type identifier (dot-separated) |
| `event_id` | string | Unique event ID (UUID, generated by server) |
| `timestamp` | string | ISO 8601 UTC timestamp |
| `payload` | object | Event-specific data |

## Server → Client Events

### `connection.ready`

Sent immediately after successful authentication.

```json
{
  "type": "connection.ready",
  "event_id": "uuid",
  "timestamp": "2024-01-15T10:30:00Z",
  "payload": {
    "user_id": "uuid"
  }
}
```

---

### `message.created`

A new message was created in a conversation the user participates in.

Sent to: all participants in the conversation (except the sender, who receives confirmation via REST response).

```json
{
  "type": "message.created",
  "event_id": "uuid",
  "timestamp": "2024-01-15T10:30:00Z",
  "payload": {
    "message": {
      "id": "msg_uuid",
      "client_id": "client_uuid",
      "conversation_id": "conv_uuid",
      "sender_id": "user_uuid",
      "sender": {
        "id": "user_uuid",
        "display_name": "Alice",
        "avatar_url": null
      },
      "content": "Hello!",
      "message_type": "TEXT",
      "created_at": "2024-01-15T10:30:00Z"
    }
  }
}
```

**Client behavior on receive:**
- Add message to local message list
- Update conversation list (last message, ordering)
- Send `message.delivered` acknowledgment back to server

---

### `message.delivered`

A message has been delivered to a recipient.

Sent to: the message sender.

```json
{
  "type": "message.delivered",
  "event_id": "uuid",
  "timestamp": "2024-01-15T10:30:05Z",
  "payload": {
    "message_id": "msg_uuid",
    "conversation_id": "conv_uuid",
    "user_id": "recipient_uuid",
    "delivered_at": "2024-01-15T10:30:05Z"
  }
}
```

---

### `message.read`

Messages have been read by a user up to a specific point.

Sent to: all other participants in the conversation (so senders can update their read receipt indicators).

```json

  "payload": {

    "user_id": "reader_uuid",
    "last_read_message_id": "msg_uuid",
    "read_at": "2024-01-15T10:31:00Z"
  }
}
```

## Client → Server Events

### `message.delivered` (acknowledgment)

Client sends this after receiving a `message.created` event to confirm delivery.

```json
{
  "type": "message.delivered",
  "payload": {
    "message_id": "msg_uuid",
    "conversation_id": "conv_uuid"
  }
}
```

**Server behavior:**
- Update receipt status from SENT → DELIVERED
- Set `delivered_at` timestamp
- Broadcast `message.delivered` to the message sender

---

### `typing.started`

Client sends this when user begins typing.

```json
{
  "type": "typing.started",
  "payload": {
    "conversation_id": "conv_uuid"
  }
}
```

**Client-side rules:**
- Throttle: send at most once every 3 seconds while typing
- Auto-stop: send `typing.stopped` after 5 seconds of inactivity
- Send `typing.stopped` when message is sent

---

### `typing.stopped`

Client sends this when user stops typing.

```json
{
  "type": "typing.stopped",
  "payload": {
    "conversation_id": "conv_uuid"
  }
}
```

## Error Events (Server → Client)

### `error`

Sent when the server encounters an error processing a client event.

```json
{
  "type": "error",
  "event_id": "uuid",
  "timestamp": "2024-01-15T10:30:00Z",
  "payload": {
    "code": "UNAUTHORIZED",
    "message": "Not a participant of this conversation",
    "original_type": "typing.started"
  }
}
```

Error codes:
| Code | Description |
|------|-------------|
| `UNAUTHORIZED` | User lacks permission |
| `INVALID_EVENT` | Unknown or malformed event type |
| `INVALID_PAYLOAD` | Payload validation failed |
| `CONVERSATION_NOT_FOUND` | Referenced conversation doesn't exist |
| `MESSAGE_NOT_FOUND` | Referenced message doesn't exist |

---

## Close Codes

| Code | Meaning |
|------|---------|
| 1000 | Normal closure |
| 1001 | Going away (server shutdown) |
| 4001 | Authentication failed |
| 4002 | Session expired |
| 4003 | Invalid token format |

## Sequence Diagrams

### Send Message Flow

```
Alice (Client)         Server           Bob (Client)
    │                    │                    │
    ├── POST /messages ─►│                    │
    │                    ├── Persist          │
    │                    ├── Create receipts  │
    │◄── 201 response ──┤                    │
    │                    │                    │
    │                    ├── WS message.created ──►│
    │                    │                    │
    │                    │◄── WS message.delivered ─┤
    │                    ├── Update receipt   │
    │◄── WS message.delivered ─┤             │
    │                    │                    │
```

### Read Message Flow

```
Bob (Client)           Server           Alice (Client)
    │                    │                    │
    ├── POST /messages/{id}/read ──►│        │
    │                    ├── Update receipts  │
    │                    ├── Update watermark │
    │◄── 200 response ──┤                    │
    │                    │                    │
    │                    ├── WS message.read ──────►│
    │                    │                    │
```

```
Alice (Client)         Server           Bob (Client)
    │                    │                    │
    ├── WS typing.started ──►│               │

    │                    │                    │

    │                    │                    │
    ├── WS typing.stopped ──►│               │
    │                    ├── WS typing.stopped ────►│
    │                    │                    │
```
